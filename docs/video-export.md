# 영상 제작용 스케일 지판 내보내기 (Premiere Pro)

> 강의·커버 영상에 얹을 스케일 지판 애니메이션을 앱 디자인 그대로 뽑는 작업의 기록(2026-10-09, 레터 일렉 솔로 기준 완성). 결과물 `letter_elec_solo_v9`가 거의 흠 없이 통과한 과정 → 모범사례.

## 1. 결과물과 작업 위치

- 결과: **4K(3840×2160) 투명 배경 ProRes 4444 .mov** 1개. Premiere에서 노래 위 트랙에 얹고, 타임라인 0초 = 악보 1마디 시작.
- 작업 폴더는 **레포 밖** `H:\Project\Project\Chorditor_video\`(커밋 대상 아님, 영상이 GB 단위라 의도적).
  - `input\` 악보(MusicXML) / `output\` 영상 / `work\` 스크립트.
- 앱 소스(`scale-data.js` 등)는 **읽기만** 한다. 스크립트가 블럭 그리드를 node로 직접 꺼내 쓴다.

| 스크립트 (`work\`) | 역할 |
|---|---|
| `render_lib.py` | 지판 렌더 라이브러리. 앱 CSS 치수(fbu 단위)를 PIL로 옮김(지판·줄·프렛선·dot·포지션 점·프렛 번호) |
| `make_letter.py` | 레터 솔로용 영상 생성(고스트·블럭 전환·슬라이드·벤딩) — 실행: `python make_letter.py 3840 2160 <출력.mov>` |
| `make_video.py`, `make_layers.py` | 초기 버전(치이카와 섬의 노래: 블럭 고정 + dot 점등, dot별 PNG·FCP XML) |
| `extract.py`, `blocks.js` | 악보에서 노트 추출, 앱 블럭과 대조(블럭 밖 음 점검) |

실행 시 `PYTHONPATH=.`(스크립트 폴더)이 필요하다(`python -I`는 현재 폴더를 import 경로에 안 넣는다).

## 2. 악보(Guitar Pro → MusicXML) 읽을 때 함정

악보는 GP7에서 MusicXML로 내보낸 `.xml`. 타브 줄·프렛이 들어 있어 블럭 위치를 모호성 없이 정할 수 있다.

- **staff 2가 타브**(staff 1은 오선). 줄 번호 1 = 높은 E(앱의 1번줄과 같음).
- **`<divisions>`가 마디마다 바뀐다.** 이전 값이 이어지는 걸 가정하지 말고 마디마다 갱신.
- **화음(`<chord/>`) 음을 건너뛰면 안 된다.** 동시에 울리는 다른 줄 음이다(이번 작업의 실수: 5마디·12마디 음이 빠졌음). 시작 시각은 직전 비화음 음과 같고 시간은 흐르지 않는다.
- `<backup>`/`<forward>` 처리 필수(오선·타브 두 줄을 한 마디에 겹쳐 적는 구조).
- **붙임줄은 한 음으로 병합**(시작+끝 길이 합산). 병합된 음이 슬라이드를 이어받을 수 있다.
- **그레이스 노트는 시간이 0**이라 본음 직전 약 0.15초를 빌려 쓴다.
- 악보에 반주 파트(드럼·베이스·피아노)가 같이 있어도 **켜는 건 기타 파트(P1)만**. 영상 길이는 악보 전체 마디 수에 맞춘다(음원과 맞추기 위함).
- 작업 전 반드시: 파트 수, BPM, 박자, 기법별 개수(슬라이드·벤딩·그레이스·화음), 프렛 범위를 먼저 뽑아 사용자에게 보고한다.

## 3. 블럭 전환 규칙

- 앱의 블럭(`ScaleData`, 키 Eb는 rootNote 3)을 그대로 쓴다. 폼 이름: A·G·E·D·C폼 / 앱 스케일 키 `major`, `mixolydian`.
- **한 화면에 프렛 7~21 고정**, 지판 전체의 스케일 음을 고스트로 깔고 현재 블럭만 100%.
- 블럭 선택 알고리즘(자동 배정 시): 슬라이드·그레이스가 아닌 일반 음 기준으로, 앞으로 가장 오래 이어지는 블럭을 고름(동률이면 시작 프렛이 가까운 쪽).
  - **슬라이드로 블럭 밖으로 나가는 음은 블럭을 바꾸지 않는다**(오버레이가 고스트 위를 지나가게).
- **사용자가 전환 시점을 직접 지정**하면 자동 배정보다 우선한다(박자·음 기준으로 지정). 이번에는 `OFF = 0.25`: 모든 전환을 **정확한 박자보다 250ms 일찍 시작**.
- 전환은 **교차 디졸브 80ms**(`XF`). 같은 구간의 고스트도 같은 시간에 교차.

## 4. 디자인 값 (최종)

| 항목 | 값 |
|---|---|
| 줄·dot·프렛선 | 흰색 `#FFFFFF`(앱 원래 검정의 반전). 프렛선·포지션 점·번호는 반투명 |
| 고스트 dot | 흰색 **35%** |
| 켜지는 dot | 파랑 `#4F7CFF` (앱 `--blue`), 켜질 때 0.2초 팝(1→1.15→1)과 0.5초 퍼지는 링 |
| 음이름 라벨 | **없음**(근음·특성음 구분도 없음, 전부 흰 원) |
| 같은 음 연타 | 끝을 0.04초 일찍 끊어 구분 |

### 슬라이드
- 기존 dot 위에서 **오버레이 dot만** 움직인다. 일반 슬라이드는 음 길이의 앞 30%는 머물고 뒤 70% 동안 이동, 그레이스 슬라이드는 0.15초.
- 자취: 흰색 사각형(불투명도 15%). **시작·끝 변이 시작·끝 dot의 지름(중심을 지나는 선) 위**, 폭은 dot 지름과 같다. 변 위치는 dot 스프라이트 크기와 같은 반올림으로 맞춘다(1px 어긋남 방지).

### 벤딩
- 1~3번줄은 아래로, 4~6번줄은 위로 움직인다. **이동거리 = 줄 간격의 80%**(`BEND_FRAC`), 온음(+2) 기준.
- **파란 잔상**: dot이 지나간 경로에 파란 잔상(시작 불투명도 60%, `TRAIL_BLUE_A`)이 남고, **먼저 지나간 곳부터** 순서대로 사라짐(약 0.5초, `TRAIL_FADE`). 시작점이 흰색으로 남아 헷갈리지 않게 하려는 의도.
- 프리벤딩은 휜 위치에서 시작해 원위치로 돌아오며 같은 잔상이 남는다. 해머링·풀링오프는 일반 탄현과 동일.

## 5. 색이 흐릿해 보이는 문제 (Premiere HLG)

- 사용자 시퀀스가 **Rec.2100 HLG(HDR)**이면, SDR(Rec.709) 소스의 흰색을 HDR 기준 흰색(약 203니트)으로 낮춰 보여줘서 **hex가 다르게 보인다**. 파일 쪽 문제가 아니다.
- RGB 코덱(QuickTime Animation)은 푸티지 해석의 색상 관리가 막혔다. **ProRes 4444(YUV)** 가 안전하다.
- 최종 인코딩: ProRes 4444, `yuva444p10le`, `scale=out_color_matrix=bt709:out_range=tv` + `setparams=colorspace=bt709:color_primaries=bt709:color_trc=bt709:range=tv`. 디코드해서 확인하면 `FFFFFF`/`4F7CFF`/`72AFFF`가 그대로 나온다.
- ffmpeg에서 색 태그를 `-colorspace` 등 옵션만으로는 안 들어갈 수 있어 **`setparams` 필터로 강제**한다(ffprobe로 `color_space=bt709` 확인).
- HLG 신호로 직접 변환해 넣는 방식(`to_hlg`)은 색이 이상해져서 쓰지 않았다.
- Premiere에서 값이 안 맞으면: 푸티지 해석 → 색상 관리 → `Rec.2100 HLG` 오버라이드, 또는 시퀀스를 Rec.709로.

## 6. 작업 방식 (잘 된 점)

1. 악보를 읽으면 바로 만들지 않고 **분석 결과(음 개수·블럭 밖 음·기법·마디 구성)를 먼저 보고**, 정해야 할 것은 기본안과 함께 한 번에 묻는다.
2. 렌더 후 **프레임을 직접 열어 확인**(슬라이드 중간, 벤딩 시작/유지, 디졸브 중간)하고, 영상 파일을 다시 읽어 **색·알파 값을 숫자로 검증**한다.
3. 사용자가 수정을 말하면 **한 번에 하나의 의도만 바꿔서** 새 파일(v2, v3…)로 뽑는다. Premiere가 열고 있는 파일은 덮어쓰기·삭제가 안 되므로 이름을 바꿔 저장한다.
4. 확인하지 못한 것(Premiere에서의 실제 화면, 전체 영상의 모든 순간)은 **확인 못 했다고 명시**한다.
5. 임시 확인 파일은 만든 쪽에서 정리하되, 삭제 전에 사용자에게 묻는다.

## 7. 주의 (도구)

- 사용자가 도구 실행을 중간에 거절해도 **명령이 이미 실행된 경우가 여러 번 있었다**(파일이 만들어져 있음). 거절 직후엔 결과 폴더를 먼저 확인한다.
- 한글 파일명 출력이 콘솔에서 깨질 수 있다. 확인용 출력은 `PYTHONIOENCODING=utf-8`로.
- 4K 렌더는 약 2분, 1.6GB. 결과 영상은 레포 밖에 둔다(커밋 금지).
