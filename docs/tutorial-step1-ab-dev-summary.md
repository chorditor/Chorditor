## 1. 뭘 했나 (한 줄 요약)

step1 순서 실험(A=에디터 먼저 / B=훈련소 먼저)의 **양쪽 변형 문구를 전부 채워** 브라우저에서 A/B 둘 다 처음부터 끝까지 이질감 없이 완주 가능한 상태로 만들었다. 부수적으로 훈련소 챕터의 "훈련 목록" 소개를 카드 5개짜리로 확장했다.

## 2. 구체적 변경

### 2-1. 문구 분기 (A/B 순서가 달라서 생기던 어색함 제거)

B(훈련소 먼저)로 순서를 바꾸니 기존 문구 7곳이 깨졌다 — "STEP1에서 배운 그 에디터예요" 같은 문장이 B에선 에디터를 아직 안 배운 시점에 나오는 식. 이 7곳을 A/B 각각 자연스러운 문장으로 새로 씀:

- 에디터 챕터 도입 (인사 vs "방금 사전에서 코드를 골라봤죠?")
- 코드 사전에서 에디터·노트 언급 (과거형 vs 예고형)
- 코드 사전 완료 → 다음 챕터 예고
- 훈련소 완료 → 다음 챕터 예고
- 훈련소 도입부 (B는 훈련소가 첫 챕터라 인사말이 여기 붙음)

문구 속 "STEP1", "STEP2" 같은 스텝 번호는 전부 `{S:key}` 토큰으로 바꿔, A/B 어느 쪽이든 실제 배정된 번호가 자동으로 채워지게 했다. 앞으로 3차 실험에서 순서를 또 바꿔도 이 클래스의 버그(번호 하드코딩)는 재발하지 않는다.

### 2-2. 훈련 목록 확대 (사용자 요청 반영)

기존엔 "여러 훈련 컨텐츠를 만들어뒀다"는 한 줄만 보여주고 바로 코드맞추기 1회 플레이로 넘어갔다. 지금은 카드 5개(코드맞추기·스케일훈련·코드진행리스트·주법리듬훈련·코드조합훈련)를 하나씩 하이라이트하며 "뭘 연습하고 싶을 때 좋은지" 한 줄씩 소개한 뒤 코드맞추기 플레이로 이어간다. A/B 둘 다 동일하게 적용되어 실험 변수엔 영향 없음.

### 2-3. 그 외 자잘한 수정

- 코드 사전 "검색으로 찾기" 진입 시 검색창이 화면 밖으로 밀려 있던 것 자동 스크롤로 해결
- 문구 중복 표현 정리 ("~둘러보세요" 반복 등)
- 1차 실험에서 폐기된 옛 순서(에디터→사전→노트→노트→훈련소)의 죽은 코드 완전 삭제

## 3. 실험 개요 (마케팅이 알아야 할 최소한)

| | 내용 |
|---|---|
| **무엇을 비교하나** | step1을 에디터(A, 기존)로 보여줄지 훈련소(B, 신규)로 보여줄지 |
| **왜** | 유저 70%가 안내 없이 훈련소부터 만졌는데(첫 터치 분석), step1을 에디터로 두니 완주율이 25%로 낮음 |
| **성공 기준** | started 대비 step1 완료율 25%→45%p 이상 개선되면 B 채택 |
| **대상** | 1.3.3.2 배포 이후 튜토리얼을 처음 시작하는 유저 (기존+신규 모두) |
| **표본** | 양쪽 started 각 200명 도달 시 1회 판정. 배정 500명/arm 근처가 목표 |
| **기간 추정** | **아직 계산 안 됨** — 일일 배정 속도 기준 목표 도달까지 며칠 걸릴지는 라이브 후 트래픽 보고 판단해야 함 |
