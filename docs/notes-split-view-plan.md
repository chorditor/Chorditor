# 노트 탭 태블릿 스플릿 뷰 — 계획·위험성 (iframe 프로토타입)

> 상태: 계획 단계(코드 변경 없음). 작성 2026-10-16.
> 목적: 태블릿에서 노트 탭을 누르면 **좌측 노트 목록 / 우측 악보**가 한 화면에 같이 뜨게 한다.
> 이 문서는 "iframe 방식을 테스트한다"는 결정 전의 계획과 위험을 정리한 것이다. 결과에 따라 B안(직접 통합)으로 바꿀 수 있다.

## 1. 확정된 요구사항

| 항목 | 내용 |
|---|---|
| 모바일 | 지금과 동일. 목록(`home.html` 노트 탭) → 악보(`user_project.html`) 2단계 유지 |
| 태블릿 | 노트 탭에서 좌측 = 노트 제목 목록, 우측 = 악보. 목록에서 노트를 누르면 페이지 이동 없이 우측 악보만 바뀜 |
| 좌측 패널 | 접어서 악보를 크게 볼 수 있음(코드사전 패널과 같은 개념) |
| **독바** | **절대 타협 불가 — `home.html`의 하단 독바(SPA 탭 전환 구조)를 그대로 유지** |
| 데이터 | 사용자가 만든 악보·코드·공유코드가 사라지거나 바뀌면 안 됨 |

## 2. 현재 구조 (코드 확인 사항)

- 노트 목록: `home.html`의 `#view-projects-list`(노트 탭)를 `home.js` `renderProjectsList()`가 그린다.
- 악보: 목록에서 노트를 누르면 `user_project.html?id=...`로 **페이지 이동**. 화면은 `user_project.js` `renderProjectView()`가 `#view-project`를 통째로 다시 그린다.
- 독바(`cd-dockbar`)는 `home.html`에만 있다. `user_project.html`, `library.html`, `editor.html`은 독바가 없는 B종 뼈대(탑바 + 메인).
- 악보 쪽 슬롯 수(4칸/8칸)는 `window.innerWidth >= 787` 기준, 가로 판정은 `innerWidth > innerHeight`(`.app-land`).
- `user_project.js`에 목록 관련 함수(`renderProjectsList`, `togglePin`, `renameProject`, `reorderPinned` 등)가 남아 있다(악보 뷰를 분리할 때 복사된 잔재로 추정). 현재 동작 여부는 미확인.

## 3. 검토한 안

| 안 | 방식 | 독바 | 판정 |
|---|---|---|---|
| **A. iframe** | `home.html` 노트 탭 우측에 `user_project.html`을 iframe으로 임베드 | 그대로 | **프로토타입 대상** |
| B. 직접 통합 | `user_project.js`를 `home.html`에 로드해 노트 탭 안에 악보를 직접 렌더링 | 그대로 | A 실패 시 대안. 전역 함수 충돌 정리가 큰 작업 |
| C. 새 페이지 + 독바 복제/공용화 | 목록+악보를 합친 새 페이지 | **복제본이 됨** | 독바 조건 위반으로 제외 |

## 4. A안 설계 (프로토타입 범위)

### 4-1. 임베드 규약 (작게 유지)
1. `user_project.html?id=<노트id>&embed=1` — `embed=1`이면 탑바(X 버튼)만 숨기고 나머지 로직은 그대로.
2. "노트 열기": 부모(`home.html`)가 iframe `src`를 바꾸거나 `postMessage({type:'open', id})`로 알린다.
3. 이탈 정리: 부모가 탭을 바꾸거나 페이지를 떠날 때 iframe 안 소리(재생·메트로놈)를 즉시 정지(CLAUDE.md 규칙 0-2 — 정리 함수 하나, 모든 출구 연결, `GuitarAudio.panic()`).

### 4-2. 상태 동기화
- 두 문서는 같은 origin이라 `localStorage`(`chorditor_projects`)를 공유한다.
- 악보에서 저장하면 부모 문서에 `storage` 이벤트가 오므로 좌측 목록은 이벤트로 스스로 갱신(별도 동기화 코드 최소화).
- 노트 이름 변경·삭제·핀은 목록 쪽에서도 일어난다 → 반대 방향(목록 → iframe)은 `storage` 이벤트 또는 `postMessage`로 처리. **미검증**.

### 4-3. 분기
- 태블릿(폭 기준)에서만 iframe을 띄우고, 모바일은 기존 흐름 유지.
- 분기 기준은 코드사전과 같은 폭 기준(769px~)을 우선 후보로 하되, 기존 `787px`(슬롯 8칸) 기준과 겹치는 구간은 확인이 필요하다.

### 4-4. 프로토타입 범위 (이번에 하는 것)
- `home.html` 노트 탭에 태블릿 폭에서만 iframe 우측 패널을 띄우고, 목록 선택 → iframe 악보 전환까지.
- 좌측 패널 접기는 프로토타입 이후.
- **저장·삭제 경로는 건드리지 않는다**(기존 `user_project.html` 로직 그대로).

## 5. 위험성

### 5-1. 데이터 손실 (최우선)
| 위험 | 근거 | 대응 |
|---|---|---|
| 목록 저장이 노트를 DB에서 삭제 | `saveProjects()`는 이전 id 목록에 있다가 새 목록에 없는 id를 DB에서 `DELETE`한다(`shared.js`) | 새 코드가 노트 일부만 담은 배열로 `saveProjects`를 호출하지 않게 한다. 저장 직전 "노트 개수가 줄면 중단" 가드 |
| 마이그레이션 중복 실행 | `renderProjectView`가 슬롯 8칸 변환·`slotBeatV2` 이식 후 `updateProject`까지 호출 | 렌더 경로를 새로 만들지 않고 기존 함수만 호출 |
| 동기화 덮어쓰기 | 로그인 동기화는 `updatedAt` 비교 last-write-wins | 버그 화면이 저장하면 DB까지 올라감 → 읽기 전용 단계 먼저 |
| 빠른 전환 중 저장 경쟁 | 목록에서 노트를 연타하면 앞 노트 저장과 새 노트 로드가 엇갈릴 수 있음 | 전환 직전 현재 노트의 저장 완료 후 `src` 교체(검증 필요) |
| 튜토리얼 샌드박스 | `isTutorialSandbox()`일 때 로컬·DB를 건드리지 않는 분기가 있음 | iframe 안에서도 같은 분기를 타는지 확인 |

### 5-2. 공유코드
- 코드는 16자 랜덤이고 `project.shareCode`가 있으면 재사용된다(`getOrCreateShareCode`). UI만 바꾸면 변하지 않는다.
- 단, `project.id`/`project.shareCode`/`project.content` 필드를 건드리거나 노트 객체를 복사 저장하면서 필드를 빠뜨리면 새 코드가 발급될 수 있다.
- 공유 payload에 슬롯 배열(8칸 고정)이 들어간다 → **저장 데이터의 슬롯 구조는 변경 금지**(표시만 4/8칸으로 바뀌는 것은 안전).

### 5-3. iframe 환경 특성 (실기기 검증 필요, 모두 미검증)
| 항목 | 우려 |
|---|---|
| 안드로이드 한글 IME | 가사 입력 첫 글자 분리 버그 이력(`bug_korean_ime_split`). iframe 안에서 재발 여부 |
| Capacitor 플러그인 | iframe에서 브리지(네이티브 공유, 앱 플러그인 등)가 노출되는지 |
| 오디오 | iframe 안 Web Audio의 사용자 제스처 활성화·재생 정상 여부, 부모와 컨텍스트가 분리되는 점 |
| 하드웨어 뒤로가기 / 이탈 | iframe 안 `backButton` 핸들러와 부모 핸들러의 충돌, 이탈 시 소리 정지 |
| 페이지 이동 | iframe 안에서 `editor.html` 등으로 이동할 때 iframe만 이동하는 문제 → 최상위(`top`) 이동으로 바꿔야 함 |
| 스크롤·터치 | 중첩 스크롤, `touch-action`, 드래그(팔레트 드래그 앤 드롭) 동작 |
| 안전영역 | iframe 안 `env(safe-area-inset-*)` 값 |
| 성능 | 악보 문서를 하나 더 띄우는 메모리·초기 로드 |

### 5-4. 기타
- 독바 탭 전환 시(노트 탭 → 다른 탭) iframe 안 소리·타이머 정리 누락 → 규칙 0-2 위반 가능.
- 튜토리얼 오버레이(`tutorial.js`)가 `user_project.html` 요소 id를 가리킨다 → iframe 안에서 오버레이 위치가 맞는지.
- 데이터 소스가 두 문서에 걸치므로 코드 수정 시 "어느 문서의 상태인가" 혼동 → 임베드 규약을 최소로 유지.

## 6. 안전 원칙

1. 데이터 레이어(`loadProjects`, `saveProjects`, `updateProject`, `getOrCreateShareCode`)와 노트 데이터 구조는 **수정하지 않는다**.
2. 새 화면은 읽기 전용부터. 저장 가능한 상태로 켜는 것은 별도 승인 단계.
3. 배포 전 DB `projects` 테이블 스냅샷 + 로컬 JSON 내보내기.
4. 내 계정 → `pre` 브랜치(Play 내부 테스트) → 일반 배포 순서로 단계 배포.
5. 태블릿 폭에서만 켜는 기능 플래그. 문제 시 플래그만 꺼서 즉시 복귀(기존 모바일 흐름은 영향 없음).

## 7. 검증 체크리스트 (프로토타입)

- [ ] 안드로이드: 가사 한글 입력(첫 글자 분리 없음)
- [ ] iOS: 가사 입력, 키보드 올라올 때 레이아웃
- [ ] 코드 재생·메트로놈 소리, 탭 전환·화면 이탈 시 즉시 정지
- [ ] 목록 연타(노트 빠르게 전환) 시 저장·표시 오류 없음
- [ ] 악보에서 이름 변경 → 좌측 목록 즉시 반영
- [ ] 악보 안에서 코드 에디터·사전으로 이동 시 전체 화면 이동
- [ ] 공유하기: 기존 공유코드 그대로 노출, 새 코드 미발급
- [ ] 노트 개수·코드 개수가 전환 전후 동일
- [ ] 안드로이드 하드웨어 뒤로가기 동작
- [ ] 폭 경계(768/769/787px)에서 분기 정상

## 8. 롤백

- 기능 플래그 OFF → 태블릿도 기존 목록 → 페이지 이동 흐름으로 복귀. 데이터 마이그레이션이 없으므로 되돌릴 데이터 변경이 없다.

## 9. 결정 필요(미정)

1. 임베드 분기 기준: 769px(코드사전과 동일) vs 787px(기존 슬롯 8칸 기준).
2. 좌측 패널 접기 시 접힌 상태에서 남길 핵심 버튼(재생·편집 토글 등).
3. 노트 탭 진입 시 우측 초기 상태: 마지막으로 연 노트 vs 빈 화면(노트 선택 안내).
4. 프로토타입이 실패하면 B안(직접 통합)으로 갈지, 노트 기능 자체를 별도 구조로 재설계할지.
