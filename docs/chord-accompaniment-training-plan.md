# 코드반주 훈련 — 기획 문서

> 상태: **기획 단계(2026-10-22 논의 정리)**. 디자인 → 구현 → 백엔드 순으로 진행 예정.
> 코드 진행 리스트(`progression`)와 주법 리듬 훈련(`strumming`)을 하나의 훈련으로 통합한다.

## 1. 한 줄 정의

**코드 진행을 고르고, 같은 진행에 여러 주법을 붙여가며 백킹과 함께 반주를 연습하는 훈련.**
앱 정체성(레슨 선생님) 관점에서 "반주 코드"와 "주법"을 따로 두지 않고, 실제 연주처럼 한 번에 익히게 한다.

## 2. 이름

- 메인 타이틀: **코드반주 훈련**
- 진입 페이지 서브타이틀: **반주를 연습할 코드 진행을 골라주세요!**
- 훈련소 카드는 기존 둘("코드 진행 리스트", "주법 리듬 훈련")이 **하나로 줄어든다**.

## 3. 화면 흐름

1. **진입 페이지(목록)**: 지금 코드 진행 리스트의 카드를 거의 그대로 사용. 타이틀·서브타이틀로 안내.
2. 진행을 고르면 **상세(연습) 페이지**로 이동. 큰 구조는 현재 진행 상세 페이지와 비슷하다.

### 상세 페이지 구성 (위 → 아래)

- 헤더: 타이틀 = 진행 이름, 선택 버튼, 키 셀렉터
- 코드 캐러셀
- **주법 선택 섹션(신규)** — 같은 진행에 다른 주법을 쉽게 골라가며 붙여보는 활동
- 부가: BPM 조절, 점진 가속, 백킹 스타일 선택, 세션 on/off

## 4. 핵심 규칙

### 4-1. 주법이 1순위
- 사용자가 고르는 1순위는 **주법**. 백킹 스타일은 부가 선택이다.
- 주법마다 **사용 가능한 백킹 스타일을 지정**한다(모든 주법이 모든 스타일과 맞지 않기 때문).
- 주법을 고르면 기본 백킹 스타일이 자동으로 붙고, 스타일 선택에는 그 주법에 허용된 것만 나온다.
- 추천 주법은 기본으로 두지 않는다. 넣게 되면 별도 필터로 "추천 주법만 검색"되게 한다.

### 4-2. 백킹 스타일 = 세션 한 세트
- 백킹 스타일은 **드럼 + 베이스 + 키보드를 묶은 한 세트**.
- 스타일마다 **기본 BPM**을 지정한다(발라드는 느리게, 디스코는 빠르게). **범위는 두지 않고 기본값만** — 사용자는 자유롭게 바꿀 수 있다.
- 박자는 주법이 가지고 있으므로, 주법에 붙는 백킹 세트도 그 박자(4/4, 3/4, 6/8, 셔플 등)에 맞게 만든다. **백킹 세트는 새로 제작**해야 한다.

### 4-3. 세션 4개 + on/off
- 세션: **드럼, 베이스, 키보드, 기타(주법별 사운드)**
- 세션별로 켜고 끄는 **버튼 하나**를 신설한다.
- 기타를 끄면 "직접 연주" 연습, 나머지를 끄면 "기타만 듣고 따라 하기".

### 4-4. 코드와 마디
- 4코드 진행: 한 마디에 코드 1개.
- 8코드 진행: **한 마디에 코드 2개**.
- 두 경우 모두 **1사이클 = 진행 전체를 1회 연주 = 4마디**.

### 4-5. BPM — 앱 전체 중심 규칙
- 범위는 앞으로 **통합 10~300 BPM**. 우리 앱의 중심 규칙으로 삼는다.
- 현재 코드의 범위(메트로놈 1~300, 진행 상세 40~200, 주법 30~200)를 구현 단계에서 맞춘다.

### 4-6. 점진 가속
- 느린 BPM에서 시작해 목표 BPM까지 점차 빨라지게 한다.
- 옵션 두 가지: **몇 사이클마다** 올릴지, **한 번에 몇 BPM** 올릴지.
- 범위: 10~300 BPM.
- 무료/유료 구분은 **나중에 논의** — 유료 옵션으로 둘 가능성을 열어두고 설계한다.

## 5. 피크 소모와 퀘스트

### 5-1. 피크
- **코드 진행 기준**으로 소모. 소모량은 **5개**(기존 3개에서 상향).
- 한 진행 안에서는 주법·스타일·BPM·키를 바꿔도 추가 소모 없음.
- 이탈 확인 모달, 새로고침 시 잠금 유지, 프로 플랜 무소모는 지금 규칙을 그대로 따른다.

### 5-2. 퀘스트(진행 퀘스트 + 주법 퀘스트 통합)
- 카운터는 **4사이클을 연속으로 끝까지 연주하면 1회**.
- 계속 연주하면 **4사이클마다 +1**.
- **정지하거나 주법·스타일·키를 바꾸면 누적 사이클은 0으로 리셋**(쪼개서 세는 것 방지).
- 기존 카운터 값 이관 방식(합산 여부 등)은 백엔드 단계에서 확정.

## 6. 재활용할 기존 코드(구조 파악 결과)

- 진행 데이터(`progression-data.js`/`progression-parser.js`, 도수 이름·`title`): 그대로 사용.
- 주법 데이터(`strumming-list.js`, 22개): 주법 선택 섹션의 원본. 박자·컷팅·악센트·난이도 포함.
- 코드 보이싱·캔버스(`progression-voicings.js`, `voicing-canvas.js`): 그대로 사용.
- 재생 스케줄러: **`strum-play.js`의 셀 단위 스케줄러**가 이미 "진행 × 주법" 구조(`STRUM_PROG`가 가짜 A E A E일 뿐). 점진 가속(램프)도 이미 있어 "몇 사이클마다 몇 BPM"으로 일반화하면 된다.
- 중복된 것은 통합 대상: 코드 캐러셀(상세 vs 주법), BPM 휠(상세·주법·메트로놈), 재생 스케줄러, 연습 시작 잠금.
- 스케일 훈련의 `BackingTrack`(드럼+피아노+베이스)은 스케일 전용 엔진 — 참고 대상이며 그대로 쓰지 않는다. 연습 모드의 BPM·재생·스타일 3버튼 UI는 상세 페이지 디자인에 가져온다.
- 기존 드럼 세트(`drum-sets.js`, 7개)는 박자별 드럼이 있다. 베이스·키보드는 4/4와 스윙뿐이라 3/4·6/8 등은 새로 필요.

## 7. 남은 논의

- 점진 가속의 무료/유료 선.
- 스타일을 바꿀 때 BPM 처리(사용자가 이미 BPM을 만졌으면 유지할지, 항상 새 스타일 기본값으로 갈지).
- 기존 두 콘텐츠의 이관 세부: 카운터 합산, 푸시 넛지·딥링크(`progression-detail.html?no=`) 처리, 분석 이벤트 이름 정리, DB 컬럼·퀘스트 RPC 통합.
- 3/4·6/8·셔플 등 박자별 백킹 세트의 제작 범위와 순서.
- 주법 선택 섹션의 UI 형태(디자인 단계).

## 8. 진행 순서

1. **기획**(이 문서) → 2. **디자인**(화면 구조, 5단계 스코프) → 3. **구현**(재생 엔진 통합, 3버튼, 훈련소 카드) → 4. **백엔드**(통계·퀘스트·분석·푸시 이관)
