# 리하모니 화성학 미니강의 — 스타일 가이드 (챕터 1~8 구현에서 뽑은 패턴, 2026-10-30)

> 새 챕터(9장) 강의를 기획·구현하기 **전에 먼저 읽는 문서**. 챕터 1~8 코드(`chord-combo-lecture.js`·`style.css`)를 읽고 정리했다.
> 개별 챕터 단계표·재사용 부품·미확인 목록은 `docs/chord-combo-redesign-plan.md` §10에 있다(**7·8장은 거기에 아직 기록하지 않았다** — 7·8장 흐름은 §1, 8장 세부는 §12). 이 문서는 **"어떻게 만들면 1~8장과 같은 결(같은 품질)이 되는가"** 와 진행 바 엔진 규칙(§11)을 다룬다.
> 추측이 아니라 구현된 값만 적었다. 수치 옆의 이름은 코드의 상수·클래스. 사용자가 확정하지 않은 제안은 §10에만 따로 적었다.

## 0. 한 줄 원칙
- **본체는 연출, 문구는 위쪽 보조 캡션**(style-guide §18). 단계마다 "유저가 이 순간 얻어야 할 핵심"을 먼저 정하고(CLAUDE.md 0-5) 그것만 진하게·파랑, 나머지는 옅게.
- **자리는 그 단계가 끝났을 때 보이는 모습을 기준으로 처음부터 잡고, 투명도·색으로만 등장·강조·교체**한다(같은 단계 안에서 나타날 것의 자리는 미리 잡아도 된다). 위치가 바뀌는 건 "핵심이 바뀌는 순간"에만, 그리고 의미가 보이는 움직임으로(§4).
- **항상 "지금 보이는 그 시점"에서 시각적 밸런스가 가장 좋게 배치한다(6장에서 추가, 재발 방지).** 다음 단계에서 나올 것의 자리를 미리 비워 두면 지금 화면이 한쪽으로 치우친다 — 예: 6장 표의 범례에서 25번에 나올 '서브' 자리를 미리 잡아 두었더니 14번에서 5개 범례가 왼쪽으로 쏠렸다. 다음 단계에 나올 것은 `display:none`(`lc6-off`) 등으로 자리를 차지하지 않게 두고, 나올 때 기존 요소를 새 균형 자리로 미끄러뜨린다(`slideIn`·`reflowScore`, FLIP).
- **허용되는 사전 배치**: 같은 단계의 애니메이션이 끝났을 때 보이는 것을 기준으로는 미리 배치를 생각해 둘 수 있다(그 단계 안에서 순서대로 나타나는 요소들의 자리를 처음부터 잡아 움직이지 않게). 기준은 "이 단계가 끝난 화면의 균형"이지 "챕터가 끝난 화면의 균형"이 아니다.
- **문구가 먼저, 연출은 1초 뒤, 소리는 화면이 바뀐 뒤.** 눈은 한 번에 하나만 본다.
- 사용자가 흐름·문구·강조·운지·예시 진행을 직접 정한다. 내가 임의로 바꾸지 않고, 내 계산과 다르면 사용자 값이 우선.

공통 골격: **복습/도입 → 개념(눈으로) → 소리로 확인 → 이름 붙이기 → 표기 → 주의점 → 작은별 적용 → 총정리(목록) → 활용·훈련 안내 → 공통 마무리**.
- **페이즈 = 챕터의 큰 흐름 3~4개, 칸 = 진행 바의 정지 단위(§11).** 칸 하나는 단계 1개이거나 `chainSteps`로 묶은 여러 단계(문구가 차례로 바뀜, 7·8장). 페이즈 안 칸 수에는 제한이 없다. 옛 "묶음 2~5단계" 규칙은 옛 "다음" 버튼 시절의 것이라 지금은 쓰지 않는다.
- 긴 챕터는 페이즈로 나눈다(3장 꾸밈코드/전위코드, 4장 도미넌트 → 세컨더리 → 작은별). 페이즈 사이에는 앞 장면을 지우고 문구만 있는 숨 고르기 단계를 둔다(3장 "다음은 전위코드에 대해서 배워볼게요", 8장 "이번에는 작은별을…" — `enter: clearScene`).
- 작은별: 1장 원곡, 2~4장 원곡 → 리하모니(바뀐 칸만 파랑), **5장은 4장 결과, 6장은 5장 결과를 출발점으로**(6장은 이어서 바뀐 곳을 악보 순서대로 하나씩 짚음). 4·5·6장의 기반 진행은 3마디가 `Dm7 - CM7 Am7`(5번 칸 뒤 1박의 Am7이 처음부터 보임, `SONG_TAIL`). 3장부터 **악보 모양**(§6-3). **7장은 6장 결과와 별개로 새로 만든 텐션 진행**(지정 운지 + 멜로디 충돌 주의 시연), **8장은 Cm 마이너 편곡**(`Cm7 Gm7 Fm7 Cm7 | Dm7(b5) AbM7 G7 Cm7`, 멜로디의 라·미를 라b·미b로 바꿈 — §5).
- 끝은 늘 **총정리 장면(목록·표) → 활용 한두 마디 → 훈련 안내(5·6장은 생략) → 공통 마무리(`endingStep(n)`)**. 6장의 총정리는 표(§6-5)이고 마무리멘트는 "너무 남발하지 않게 조심"으로 끝낸다. 7장은 총정리 표 3장 + 마무리멘트(`seq`), 8장은 훈련 목표 문구를 두 번에 나눠 띄운다(한 문구가 3줄 폭을 넘어서).

## 2. 문구 스타일

**구조**
- 두 줄: 1줄 = 앞 맥락·원인, 2줄 = 결론·새 개념. 줄바꿈은 의미 단위에서(`\n`). 한 줄짜리 문구는 짧은 선언·확인에만.
  - 예: `이 둘을 모두 가진 코드가 / 5도 [G7] 코드예요`, `해결할 음을 모두 가진 코드는 / 1도 [CM7] 코드예요`
- 해요체. 공통 마무리만 합쇼체("수고하셨습니다!").
- 줄 길이는 약 20자(캡션 폭 328px = 360 − 인셋 32). 넘으면 **3줄로 나누고 키워드에 강조**(문구 자리가 3줄 고정이라 무대는 안 움직임). 경계 문구는 글자 폭 추정으로 먼저 점검(한글 16.4~18px, 숫자 11, 대문자 12, 소문자 10.5, 공백 4, 자간 -0.04em).

**문형 카탈로그**

| 쓰임 | 문형 / 예 |
|---|---|
| 도입 | `N장에서는 ~에 대해 배워요/확장해볼게요!`, 복습 도입(5장) `N장에서 ~에 대해 배웠었죠!` |
| 용어 소개 | `~를 [X]라고 해요/불러요`. 정의 → 이름 순서. 처음 나오는 용어는 정의한 뒤에 쓴다 |
| 소리 직전 | `~들어봅시다!`, `~들어볼까요?`, `~해볼게요!` |
| 질문 → 답 (5장) | `~지 않을까요?` → 다음 단계 `맞아요! ~` |
| 비유 이어받기 | 4장 `베스트 프랜드가 놀러 온 셈` → 5장 `친구의 친구가 놀러 온 셈` |
| 예고·한계 | `왜 그런지는 나중에 알려줄게요`, `정해진 공식은 아니라서 곡에 어울린다면 자유롭게` |
| 연결어 | 그래서·그런데·이렇게·하지만·또·그리고·말하자면으로 앞 문장을 받는다 |
| 조건이 둘 | 별개 단계로 나누고 각각 자기 장면을 붙인다(5장 메이저일 때/마이너일 때) |
| 마무리 | 소감(`seq`) → 의미 → 활용 → 훈련 안내 → 공통 마무리 |
| 궁금하게 → 연출로 답 → 완료 문구 (6장) | `혹시 우연일까요?` → `우연이 아니에요!` / `그런데 이 두 음의 순서를 바꾸면...!`(말줄임) → 연출이 먼저 답을 보여 주고, 완료 문구 `또 다른 도미넌트 코드인 Db7이 완성돼요!`는 **다음 단계(문구만)** 에서 |
| 부담 덜기 (6장) | `사실 이걸 찾는 건 꽤 어려운 부분이에요 / 하지만 쉽게 찾는 요령이 있어요!` |
| 조심시키기 (6장) | `실제로 어울리는지는 곡마다 달라서 / 너무 남발하지는 않게 조심해야 해요` |
| 앞 챕터 호출 (5·6장) | 5장 `2장에서 ~ 배웠었죠!`, 6장 `4장에서 본 두 긴장음`·`5장에서 만든 진행이에요` |

**강조 (`em('…')`, 파랑)**
- **사용자가 괄호로 지정한 말만.** 용어 한 단어 또는 핵심 한 단어. 3줄 문구는 키워드 하나(`[2도 마이너]`, `[논-다이어토닉]`, `[변형]`).
- 이름표("도미넌트"·"논-다이어토닉 코드")나 바뀐 코드 이름 전체에는 강조색을 쓰지 않는다(바뀐 음만).
- 코랄은 긴장음에만(`emT`, 무대의 긴장음과 같은 색). 따옴표로 강조하지 않는다.
- **같은 문구에서 이미 나온 용어는 두 번째에만 강조**(6장 — 첫 줄 `트라이톤`은 강조 없이, 둘째 줄 이름 `[트라이톤 대리 도미넌트]`에만). 중복 강조 금지.
- 사용자 표기 약속: `/` = 줄바꿈, `->` = 별개 단계, "(순서대로 나열)" = `seq`(한 줄씩).

**영어 병기 (6장)**
- 한국어 낱말 아래에 영어를 작은 라벨로 덧붙인다: `an('트라이톤', 'Tritone')` → `.lec-an`(inline-block) + `.lec-al`(absolute, 11px 회색, 강조 파랑을 물려받지 않음). 라벨이 absolute라 **줄 높이·행간은 한국어 글자 기준 그대로**.
- 라벨은 **문구의 마지막 줄에만** 쓴다(아래 줄이 있으면 라벨이 그 줄과 겹침 → 문구를 2줄로 줄여 셋째 줄 자리에 놓이게 함). 한 줄이 328px에 거의 차면(6장 첫 줄 약 312px) 기기에서 접히는지 확인.
- 번역 규칙(번역은 아직 없음): 영어판은 낱말 자체가 영어라 라벨 없음, 스페인어판은 영어 용어를 그대로 쓰고 이탤릭으로 구분, 일본어는 미정. `an()` 한 곳에서 언어별로 갈라 처리한다.

**하지 않는 것**: 주어 생략으로 앞 문장과 끊기, 정의 전에 용어 쓰기, 한 문구에 강조 여러 개, 문구마다 습관적으로 강조.

- **문구 → 1초 → 연출 → 소리** 순서 고정. 설명이 길면 읽을 시간(`READ` 1.8초)을 두고 소리를 낸다(3장 sus4 해결).
- **문구만 있는 칸의 길이 = 최소 간격 − `AUTO_GAP_MS` = 3.6초**(`durs`). 문구 둘이 한 칸(`chainSteps`)이면 문구마다 이 간격이 적용된다.
- **장면 → 문구 → 문구**: 같은 장면 위에 문구만 있는 단계(`textOnly`)를 2~3개 연달아 얹어 의미를 풀어 준다. `seq`는 소감·여운·마무리에만, 정보·논리 문구는 두 줄을 한 번에.
- `text: ''`(문구 없이 장면만)는 목록·총정리처럼 장면이 본체일 때. 앞 문구가 먼저 사라지고 다음 단계에서 문구가 뜬다.
- 소리가 있는 묶음 끝 단계는 `.ms`(소리 꼬리까지)를 지정. 동요 단계는 14.5초.
- **특수 정지를 만들지 않는다(6장 결정)**: "생각할 시간"용 긴 정지(7초 → 3.5초)를 실험했지만 결국 없애고 **다른 단계와 같은 규칙**(문구 최소 간격 — 6장 당시 3초, 2026-10-30부터 4초)으로 갔다. 특수 정지가 필요해 보여도 먼저 최소 간격으로 충분한지 본다.
- **완료 문구는 연출 뒤에(6장 18→19)**: 질문 문구("순서를 바꾸면...!") → 연출이 바로 답을 보여 줌(느린 애니메이션) → 완료 문구는 다음 단계(`textOnly`)로 분리. 문구가 늘 먼저 뜨는 엔진 규칙 안에서 "답이 먼저 보이는" 순서를 만드는 방법.
- **소리 없이 먼저 띄우기(6장)**: 바꾸기 전 진행은 소리 없이 화면에만 두고 **바뀐 진행만 재생**(13·20번), 등장만 필요하면 소리 없음(4번). 앞 챕터는 원래 → 바뀐 순서로 둘 다 재생했다 — 어느 쪽인지는 사용자가 정한다.

- 꺾쇠(5장): 두 글자의 폭을 재서(`Range`) 가운데에서 가운데까지 선 → 우리 표기로 교체.

## 5. 소리와 연출의 연계
- **화면 → 소리**: 이름·음이 바뀐 뒤에 소리(`SETTLE_MS`, 또는 연출 완료 후 `S` 2.2~2.8초). 연출은 소리보다 약 100ms 빠르므로 `LEAD_MS`만큼 늦춰 맞춘다.
- **울리는 것만 파랑, 나머지는 옅게**: `hot`(열), `hotSlots`(칸), `playNames`(이름), `quietRows`(줄).
- **전후 비교 소리**: 원래 재생 → 바꿈 → 바뀐 것 재생 → (되돌림 → 재생). 3장 C → Csus2 → Csus4 → C(해결), 4장 G7 → CM7 / G7 → Cm7, 5장 `Gm7 C7 FM7` → `Gm7(b5)` 교체 → 재생 → 원래대로.
- 마지막 코드는 길고 세게(1.4~1.9초, 끝 코드 `rel` 0.8~1.0), 중간 코드는 짧게(0.72초, 0.4).
- **운지는 사용자 지정값이고, 구성음을 계산해 검증한다(6장).** `FM7 x x 1 3 3 3`은 D# A# D G라 FM7이 아니었다(→ 확인 후 `x x 3 5 5 5` = F C E A). 한 구간에서만 쓰는 운지는 전용 상수로 분리한다(`BM7B5_CMP6` = 10번 비교에서만, `v6sub` = 20번 `Dm7 Db7 CM7`에서만, 6장 `FM7`은 `VOICINGS6`).
- 코드열 재생 속도: 7개 코드 0.75초/개 + I 한 번 더, 진행 칸은 1.0~1.4초/칸. 스케일은 레가토(1장 420ms, 4장 220ms 간격, 다음 음이 시작될 때까지 울리고 0.18초 페이드).
- 동요: 코드는 약하게(`'weak'`, 기타 트림 0.3), 멜로디는 피아노(게인 1.4). 가사는 부른 글자 진하게·지금 글자 파랑·아직은 흐리게. 박자를 쪼갠 칸은 1박씩.
- 소리가 있는 단계는 이탈(CLAUDE.md 0-2)에서 하드컷(`panic`·`resetPiano`)이 되도록 `strum`/`piano` 래퍼만 쓴다.
- **사용자 운지도 구성음을 계산해 검증하고 어긋나면 보고한다(8장도 해당)**: `Cm7 x 3 5 3 4 5`는 1번줄 5프렛이 A라 `C G Bb Eb A`(Cm7(13))였다 → 보고 후 사용자가 `x 3 5 3 4 3`으로 확정. 운지가 모자라면(`EbM7`·`Bb7`) 구성음을 계산한 제안값을 내고 승인받는다.
- **코드를 바꾸는 편곡은 멜로디와 부딪히는지 먼저 본다(8장)**: 마이너 편곡은 `Fm7`·`AbM7` 칸에서 원곡 멜로디의 라(A)·미(E)가 부딪혀 멜로디를 라b·미b로 바꿨다(`MELODY8`). 멜로디를 바꾸는 건 사용자 승인 사항 — 해석을 보고하고 확인받는다.

## 6. 배치·위계

**6-1. 세로 구조**: 문구(위, 가운데 정렬, **3줄 자리 고정·맨 위 정렬, 아래 여백 16px**) → 무대(높이 **220px 고정**, 위쪽 정렬, 장면마다 `padding-top`만 조절: 16~48px) → 버튼. 360×640에서 한 화면에 들어가는지 확인.

**6-2. 글자 위계**
- 외울 것(코드 이름·도수·기능 이름) `--type-title-lg`, 과정(음이름) `--type-title`·회색, 큰 예시는 한 크기·한 색. 한 표기 안에서 글자 크기를 섞지 않는다(`V7/II`).
- 이름은 로마자와 달리 m·dim 같은 품질도 근음과 같은 크기. `(b5)`는 항상 위첨자(`_ccFormatB5`), 도수는 `.lec-rq`.
- 위에서 아래로 중요한 순서: 코드명 → 번호 → 줄어든 음.
- 색 의미: 파랑 = 지금 핵심·바뀐 것, 기능 색(해결 파랑 `--blue` / 예비 보라 `--icon-purple` / 긴장 코랄 `--icon-coral`), 옅은 회색 = 안 울리는 것·지나간 것. 새 색 금지, 카드·박스 금지(style-guide §0).

**6-3. 작은별 악보 (3장부터)**
- 한 줄 2마디(8박) × 두 줄. 가로선 위 코드(칸 시작 박에 왼쪽 정렬, 겹치면 오른쪽으로 밀어냄 — 억지로 끼우지 않음), 아래 가사(박자 무시, **마디 단위로 묶어 마디 시작에 왼쪽 정렬**).
- 선은 **회색(`--text-muted`) 2px 정수**(1.5px는 양끝이 서로 다른 굵기로 보임), 양끝 세로선 24px·마디선 14px(짧게). 코드(18px)·가사(16px)는 가로선 바로 옆(약 4px). 한 줄 높이 64px, 줄 사이 16px.
- 쪼갠 칸(5장)은 Rel.IIm이 칸 시작, 원래 코드가 1박 뒤(Rel.IIm이 더 넓으면 그만큼 뒤). 뒤쪽에 덧붙는 코드(6장 `Bdim7` = `lc6-aft`, 기반 진행 5번 칸의 `Am7` = `lc6-tail`)는 원래 코드 1박 뒤.
- **코드가 많은 줄(6장 아래 줄 7개)은 그 줄의 코드 글자만 줄여서 선 안에 맞춘다**(`--sc-fs`, 12px 하한, `layoutScore`가 넘치면 4번까지 반복). 겹치게 끼우지도, 선 밖으로 내보내지도 않는다. 마디선에 걸치는 코드는 허용(기기에서 확인).

**6-4. 폭·정렬 규칙**
- 진행은 시간 순서대로 **왼쪽 → 오른쪽**, 표는 세로로 쌓는다(가로 나열은 폭이 모자랐다 — 5장 `F#m7(b5)` 약 72px). 칸 폭은 줄마다 같게 고정(80/40/56px, 칸 사이 24px), 목록도 같은 폭.
- 7th 7개는 위 4개(80px 간격) + 아래 3개(글자 폭을 재서 여백 같게) 두 줄.
- **도수·코드 7개 나열은 표가 아니다 — 가로로(1장 한 줄, 2장·8장 4+3 두 줄).** 세로 표는 줄 = 종류인 큰 표(6장)에만. 8장에서 비교표를 세로로 만들었다가 지적받았다(§7-20).
- 아래 줄 글자가 위 줄보다 넓어도 열이 벌어지지 않게 아래 줄 칸 폭을 0으로(가운데 정렬 오버플로, 4장 `V7/II`·5장 `Rel.II → V7 / IV`).
- 높이 예산: 5줄 + 이름표 ≈ 206px, 악보 두 줄 ≈ 144px, 모두 무대 220px 안.
- 폭 상한: 진행 280px(4칸), 요약 300px, 5장 f층 300px, 쪼갠 칸 시연 220px. 예시 진행은 연속 단계에서 통일(4장 `Dm7·A7`, 5장 `Gm7 C7 FM7`).

**6-5. 표 (6장 대체 코드 표)**
- **열 = 다이어토닉 코드**(`CM7 Dm7 Em7 FM7 G7 Am7` — `Bm7(b5)`는 향하는 도미넌트가 없어 뺌), **줄 = 위에서 아래로 다이어토닉 / 도미넌트 / 1전위 / dim7 / m7(b5)(타겟이 메이저인 열만) / 서브.** 처음에 줄=도미넌트·열=종류로 짰다가 사용자가 반전시켰다 → 표의 축은 기획(단계표 승인) 때 먼저 확인.
- 열 폭은 가장 넓은 칸에 맞춰 모두 같게(`fitTable`), 글자는 칸 가운데, 표 전체가 가운데. 표가 무대 폭(328px)보다 넓으면(약 380px) **통째로 scale**(약 0.87배 ≈ 글자 12px, 11px 하한 안; 스타일 가이드 §17 "사진 확대" 방식 — 한 벌로 디자인하고 scale만).
- 줄마다 색(도미넌트 코랄 / 1전위 파랑 / dim7 보라 / m7(b5) 초록 / 서브 분홍, 다이어토닉은 기본색)을 **처음부터** 입히고, 줄 이름 범례는 **표 밖**(축소되지 않음)에서 줄과 함께 나타난다. 범례와 표 사이 24px. 높이 ≈ 216px로 무대 220px에 거의 찬다. 파랑·보라·코랄은 기능 색과 겹치지만 이 표에서는 줄 구분용.
- 줄은 위에서 아래로 한 줄씩(stagger 100ms), 서브 줄은 25번에 더해진다. **그 전엔 자리도 차지하지 않는다**(`lc6-off` = display:none) → 범례가 5개 기준으로 가운데, 25번에 6개 기준으로 재배치(§0 밸런스 규칙).

**6-6. 7코드 목록 (8장 `list` — 이름 위 · 도수 아래)**
- 폭 320px(칸 80px × 4), 둘째 줄 3개는 가운데, 줄 사이 16px. 칸 = 코드 이름(`--type-title` 18px, 600, 근음·품질 같은 크기, `(b5)`는 위첨자) 위 + 도수(`--type-label-lg` 14px, 600, `--text-secondary`) 아래, 간격 4px. 높이 ≈ 100px(이름표 포함 ≈ 160px).
- 목록 위에 작은 이름표(label-lg, 보조색)를 둘 수 있고 같은 자리에서 글자가 바뀐다(메이저 → 마이너, C 메이저 → A 마이너).
- 도수 표기: 숫자 부분은 크게, 품질(`m7` 등)은 `.lec-rq`(12px)이되 8장 목록에서는 숫자와 같은 두께로 상속(숫자 400·품질 700이면 달라 보임, §7-23). 앞의 `b`는 `.lc8-bb`로 감싸 필요한 칸에서만 파랑(`.lc8-bon`).
- 울리는 코드만 이름·도수를 함께 파랑(`hotCells8`), 8번째 소리(1도로 돌아옴)는 첫 칸.

## 7. 사용자 지적 이력 → 6장 이후 선제 체크리스트
1. 강조 남발(4장) → 지정한 말·그 단계 핵심 하나에만.
2. 문구가 앞 문장을 못 받음(4장) → 주어 생략 금지, 용어 정의 후 사용, 장면 점프 전 연결 문장.
3. 표기 안에서 글자 크기 섞음(4장) → 한 크기·한 색.
4. 가로 나열 폭 부족(5장) → 진행은 좌→우, 표는 세로.
5. 문구가 너무 빨리 넘어감(5장) → 엔진 최소 간격(자동, 지금 4초). 새로 손대지 않는다.
6. 2줄↔3줄 전환으로 연출이 움직임(5장) → 문구 자리 3줄 고정(자동).
7. 3줄 문구가 읽기 어려움(5장) → 키워드 강조.
8. 악보 선 두께·색·크기·간격(3~5장) → §6-3 값 그대로.
9. 예시가 문구와 장면에서 다름(5장) → 문구를 장면에 맞춘다.
10. 운지·표기 해석 → 사용자 지정값 우선. 오타로 판단한 것은 보고하고 고친다(4장 `D7` → `A7`, 5장 `V7/II` → `V7/IV`).
11. 마크업에 없는 클래스를 CSS가 가리킴 / 자기 단계 전에 보이는 배경·테두리(2장) → 부모 `display`·클래스 실존·컨테이너 투명도 확인(CLAUDE.md 0-1).
12. 나중 단계에 나올 것의 자리를 미리 비워 두어 지금 화면이 한쪽으로 치우침(6장 표 범례의 '서브') → §0 밸런스 규칙: 지금 보이는 것 기준으로 가운데·균형을 맞추고, 나올 때 기존 요소를 재배치(`slideIn`).
13. 표의 축(열/줄)을 사용자 의도와 반대로 짬(6장) → 단계표 승인 때 "열이 무엇이고 줄이 무엇인지"를 함께 적어 확인(§6-5).
14. 입력된 운지가 코드 구성음과 다름(6장 `FM7 x x 1 3 3 3`) → 구현 전에 구성음을 계산해 검증하고, 의심되면 확인한다. 5개 값만 온 운지(`G#dim7 4 x 3 4 3`)는 구성음으로 마지막 줄이 `x`임을 확인하고 해석을 보고.
15. 오타 의심(6장 문구의 `Bb7` ↔ `Db7`) → 이론상 맞는 쪽으로 구현하고 반드시 보고.
16. 소리 범위(6장 17번) → 설명하는 것만 재생(B·F 두 음), 코드 전체를 쓰지 않는다.
17. 같은 문구에서 용어를 두 번 강조(6장 `트라이톤`) → 두 번째에만.
18. 기반 진행(작은별)을 바꾸면 4·5·6장 전체에 일괄 반영(`SONG_TAIL`) — 한 장만 고치면 "앞 장에서 만든 진행이에요"가 어긋난다.
19. 영어 라벨이 아래 줄과 겹침(6장 설계) → 라벨은 문구의 마지막 줄에만(§2).
20. 도수 7개 비교를 세로 표로 만듦(8장) → 도수·코드 7개 나열은 가로(1장 7열, 2장·8장 4+3). 6장의 "표는 세로"는 줄이 종류인 큰 표에만 해당(§6-4). 기획할 때 "비슷한 장면을 앞 챕터에서 어떻게 보여 줬는가"를 먼저 찾는다.
21. 나란한 조 장면도 세로 표로 만듦(8장) → 4+3 가로 목록 하나에서 코드 이름만 칸 사이를 이동(§4).
22. 7장 부품(`cell`)을 복사하며 음이름 아래 번호(1~7)가 딸려 옴(8장) → 부품을 재사용해도 이 칸의 핵심이 아닌 요소는 뺀다. "무슨 의도냐"는 물음에 핵심으로 답할 수 없는 요소는 두지 않는다.
23. 도수 안 숫자(400)와 품질(`.lec-rq`, 700)의 두께가 달라 보임(8장) → 도수는 숫자·품질을 같은 두께(600, 코드 이름과 같음)로(§6-6).
24. 문구 사이 간격을 전체적으로 늘려 달라(3 → 4초) → 상수 하나(`CAPTION_GAP_MIN_MS`) + 전 챕터 `durs` 재측정 + 전 챕터 회귀 시뮬레이션(§11).
25. 단계를 합치면 번호가 한 칸씩 밀린다(8장) → 합친 직후 새 칸 목록을 보여 주고, 사용자가 쓰는 번호의 기준(옛 목록/새 목록)을 확인한다.
26. 사용자 문구의 오타(`아니예요`)와 줄 폭 초과(훈련 목표 423px) → 오타는 고치고 보고, 줄 폭은 줄바꿈 의도를 지키며 3줄로 나눠 제안. 나눠 띄우길 원하면 `->`로 별개 단계(8장 훈련 목표).
27. 코드를 바꾸는 편곡에서 원곡 멜로디가 새 코드와 부딪힘(8장 마이너 작은별) → 부딪히는 음을 계산해 멜로디를 같이 바꾸는 안을 보고하고 승인받는다(§5).

## 8. 새 챕터 착수 순서 (협업 프로토콜)
1. 이 문서와 plan §10-2·§10-4를 읽는다. 챕터 학습목표·출제 로직은 plan §1·§7.
2. 사용자가 **흐름·문구**를 준다(5장 방식: 번호 매긴 흐름 → 사용자가 문구를 단계마다 고침). 모호한 표기는 §2의 약속대로 해석하고 해석한 내용을 보고.
3. 내가 **단계표**(번호 · 문구 · 연출 · **핵심**)를 만들어 승인받는다(CLAUDE.md 0-5). 지정 운지·예시 진행이 필요하면 구현 전에 사용자에게 받는다.
4. 구현: `buildStageN`(무대 층) → `STEPS_CHn`(칸으로 묶을 단계가 있으면 낱개 `STEPS_CHn_RAW` + `chainSteps`로 조립) → `.ms` → `GROUPS_CHn`(페이즈 3~4개, §11) → `DURS_CHn`(시뮬레이션 실측, §11) → `LECTURES[n]` → `buildFor`·`resetView`·`seek` 안의 `is-chN` 클래스 목록 → `chord-combo.js`의 `COMBO_V2_LECTURE_READY`.
5. 검증: 문법 검사 + 가상 시계 시뮬레이션(묶음 수·간격·오류·소리 횟수). **렌더링은 못 본다 → 위치·색·겹침은 CSS·마크업을 읽어서 확인하고, 기기 확인 전에는 "미확인"으로 보고.** 프리뷰로 스스로 검증하지 않는다. 시뮬레이션 5모드(dur·seek·seekback·lock·rules, §11)를 돌리고, 공통 상수를 바꿨을 땐 전 챕터를 돌린다.
6. 기록: 단계표·결정 사항·미확인 항목을 plan §10에 추가하고, 이 문서에 새 패턴이 생기면 갱신. 문서·코드는 요청받은 파일만 수정. **단계를 합치면 칸 번호가 바뀐다 — 합칠 때마다 새 목록을 보여 주고 번호 기준을 확인한다(§7-25).**
7. 구현 뒤 수정은 하나씩 바로 반영하고(문구·간격·운지·소리 범위) 시뮬레이션을 다시 돌린다. 새 규칙이 생기면(예: §0 밸런스 규칙) 이 문서에 먼저 적고 plan §10-7에서 가리킨다.

(6장 진행 방식: 사용자가 번호 매긴 흐름 → 내가 문구 초안이 든 단계표(줄 접힘을 글자 폭 추정으로 먼저 점검) → 사용자가 번호별로 문구를 고쳐 확정 → 필요한 운지 목록을 요청해 받음 → 구현 → 소소한 수정 반복.)

## 9. 챕터를 거치며 높아진 점 (6장도 이 방향)
- 1장 한 격자 → 2장 층 겹치기 → 3장 시연 위젯(가운데에서 갈라지는 코드) → 4장 표기 그리드 → 5장 표·푸시·꺾쇠·분할 → 3~6장 악보 → 6장 행렬 표(scale-to-fit)·세로 괄호·느린 완성·기존 요소 재배치 → 7장 텐션 표(내추럴/얼터드 색)·꺾쇠·단계 묶기 → 8장 제자리 교체 비교·칸 사이 이름 이동·마이너 편곡.
- **설명 → 시연 → 소리 → 비교 소리**로 같은 개념을 눈과 귀로 두 번 확인.
- 움직임을 의미 단위로(굴러 바뀜, 갈라짐, 밀어서 자리 열기, 쪼개기).
- 같은 부품을 재사용(`w3`·`rollNote`·`setName`·`layer4`·`playSeq`·`openSplit`·`scoreHtml`). 새 챕터는 부품을 먼저 찾고, 없을 때만 만든다. 6장은 새로 만든 것이 표·괄호·재배치뿐이고 나머지(비교 위젯, 갈라짐, 표기 격자, 악보)는 앞 챕터 부품을 그대로 썼다.
- 8장은 새로 만든 것이 4+3 목록·칸 사이 이름 이동·마이너 편곡뿐이고, 스케일 격자(1장)·스케일 칸(7장)·악보(§6-3)·지정 운지 재생은 앞 챕터 부품을 그대로 썼다.

## 10. 9장으로 가져갈 것 (제안 — 사용자 미승인, 흐름은 사용자가 정한다)
- 9장(모달 인터체인지)은 8장의 "나란한 조" 장면이 출발점이다. 같은 key의 두 진행을 위아래로 비교하거나(악보 두 줄), 8장 방식으로 **7코드 목록의 이름만 칸 사이를 이동**(`reorderKey8`)시켜 "빌려오는" 코드를 보여 줄 수 있다.
- 재사용 부품: 7코드 목록(4+3 가로, 이름 위·도수 아래, §6-6), 제자리 교체 비교(§4), 이름 이동 FLIP(§4), 악보(§6-3), 지정 운지 재생(`playV8`·`playFixed`), 칸 합치기(`chainSteps`).
- 필요한 데이터: 모달 코드 9종(`EbM7 Fm7 AbM7 Dm7(b5) DbM7 Fm6 F#m7(b5) Bb7 BbM7`)의 지정 운지 — 구성음을 계산해 검증한 뒤 사용(§5). 9장 퀴즈의 도수는 트라이어드 도수(`bIII IVm bVI bVII7 …`, plan §7-8).
- 도수 표기 주의: 8장 퀴즈 힌트는 트라이어드 도수(`Im IIdim bIII …`)이지만 8장 강의는 7th 도수(`Im7 IIm7(b5) bIIIM7 …`)를 썼다(사용자 승인). 9장도 단계표 때 어느 쪽인지 확인한다.
- 아직 안 다룬 것: 퀴즈 카드의 `#Idim7` 같은 dim7 도수 표기 설명(plan §10-8 미정).

## 11. 진행 바 엔진 (2026-10-30, 1~8장 전부 적용 — 앞으로 새 강의는 이 엔진을 전제로 설계)
하단 "다음" 버튼 대신 페이즈 진행 바. 코드는 `chord-combo-lecture.js`의 "진행 바" 절(`pbar*`·`seek`·`halt`·`advance`·`skipGroup`·`goGroup`), 마크업 `chord-combo.html` `#lec-pbar`, CSS `style.css` `.lec-pbar-*`.
`LECTURES[n].durs`가 있는 챕터가 진행 바를 쓴다(1~8장 전부). 옛 "다음" 버튼(`#combo-v2-lec-next`)은 마크업에만 남고 섹션 `.is-pbar`에서 숨김. 화면 터치 건너뛰기는 없다.

**왜 이 엔진을 전제로 하나 (사용자 확정)**
- 단계를 잘게 쪼개도 흐름이 안 끊기고, 칸 하나가 "다시 듣기 단위"가 된다. 단계 설계를 더 디테일하게 할 수 있다.
- 단계가 짧고 핵심이 하나면 끝난 화면이 분명해서 빨리 돌리기 재현이 정확하고, 수정 영향이 칸 하나로 좁다 → 애니메이션 관리가 쉽다.

**구조**
- 페이즈 = 챕터의 **큰 흐름 3~4개**(`GROUPS_CHn`의 원소, 값은 칸 번호 0부터). 페이즈 구분은 사용자가 정한다. 바 하나 = 지금 페이즈 하나, 칸 길이 = 실제 시간 비율(`durs`).
- **칸 = 정지 단위.** 모든 칸은 끝에서 멈추고(마커가 칸 끝 세로선에 선다) "다음"이 켜진다. 칸 안의 연출은 자동으로 이어지지만 칸과 칸 사이는 자동으로 넘어가지 않는다. 칸 하나는 단계 1개 또는 `chainSteps`로 묶은 여러 단계(아래).

**화면 (위 → 아래)**
- 마커(아래로 뾰족한 오각 방패 16×20, `--brand`, 위아래 2px·1.6초로 둥둥) → 게이지 4px(배경 `--gray-light`, 채움 `--brand`) → 버튼 두 개를 폭 절반씩: **이전**(`cd-btn--gray`) / **다음**(`cd-btn--blue`). 누르면 `pop.mp3`(`_playSfx`).
- 경계 세로선 2px: 안 찬 곳 `--text-muted`, 찬 곳 흰색(`.is-on`). 칸 터치 영역은 게이지 위아래로 넓혀 44px.
- 마지막 칸이 끝나 멈추면 "다음" 글자가 **"완료"**로 바뀐다(`isLastCell`). 강의 중엔 개발 빌드 도구 줄(`#combo-v2-devbar`)을 숨김(바를 가림).

**이동 규칙**

| 조작 | 동작 |
|---|---|
| 칸 터치 | 그 칸 처음부터 — 무대 재생성(`buildFor`) → 앞 칸 빨리 돌리기(소리 없음) → 그 칸부터 평소 재생 |
| 다음 (칸이 끝나 멈춘 상태) | 다음 칸 시작(페이즈 마지막 칸이면 다음 페이즈 첫 칸, 마지막 페이즈의 마지막 칸이면 완료 처리) |
| 다음 (이미 들은 칸을 재생 중) | 지금 칸을 바로 끝내고(`skipGroup`) **곧바로 다음 칸을 재생**(`L.autoNext`). 마지막 칸이면 끝난 채 멈추고 버튼이 "완료" |
| 이전 (칸이 끝나 마커가 멈춘 상태) | 이전 칸이 아니라 **지금 칸을 처음부터 다시**(`seek(L.step)`). 첫 칸도 멈춘 뒤엔 눌림(재생 중엔 갈 곳이 없어 닫힘) |
| 이전 (재생 중, 페이즈 안) | 이전 칸 처음부터(`seek`) |
| 이전 (재생 중, 페이즈 첫 칸) | 이전 페이즈를 **다 들은 상태**(마지막 칸의 마지막 화면·문구, 게이지 100%, 다음 대기)로 — 다시 재생하지 않음 |

**페이즈 전환 규칙 (전역, 2026-10-30 사용자 확정 — 모든 챕터·새 강의 공통, `crossPhase`)**
- 페이즈를 넘어갈 때는 반드시 **직전 페이즈의 화면 없이 백지에서 시작**한다. 앞 페이즈의 장면을 그대로 쓰는 단계여도 이어 붙이지 않고 **새로 생성**한다.
- 페이즈가 끝나 멈춰 있는 동안은 화면을 그대로 둔다(끝날 때 지우지 않음). "다음"을 누르는 순간 **애니메이션 없이 즉시** 무대·문구·진행 바(새 페이즈의 칸, 게이지 0%)를 모두 비워 **완전히 빈 화면을 0.2초**(`PHASE_BLANK_MS`, 처음 0.5초에서 단축) 보여 준 뒤, 무대 DOM을 새로 만들어 앞 단계를 빨리 돌려(`seek`) 이 페이즈의 시작 장면을 복원하고 첫 문구·연출을 시작한다.
- 복원한 장면은 갑자기 튀어나오지 않는다. 페이즈 첫 칸이 `enter` 없는 칸이면(1장 P2~P4, 2장 P2, 5장 P2 — 앞 페이즈 장면을 이어서 바꾸는 칸) **요소를 하나씩 새로 만들어 올린다**(`phaseBuild`): 보이는 요소(`.is-in`, 켜진 층 `.is-on`)를 전환 없이 먼저 끄고, 문서 순서(왼쪽 열부터·위에서 아래로)대로 `transition-delay`를 늘려 가며 다시 켠다(총 `PHASE_BUILD_MS` 400ms 안, 첫 연출 시작 전에 끝남). 클래스는 같은 순간에 원래대로 돌아와서 빨리 돌리기·건너뛰기의 화면 상태는 그대로다. 무대 전체도 첫 문구와 함께 서서히 나타난다(`phaseFadeIn`, `FADE_MS`)는 안전망.
- 페이즈 첫 칸에 `enter`(앞 장면 치우기)가 있으면(2장 P3, 3장 P2~P3, 4장 P2~P4, 5장 P3, 6장 P2~P3, 7장 P2~P4, 8장 P2~P3, 9장 P2~P3 — 16곳(5장은 페이즈를 합쳐 P3 하나)) 만들어 올릴 장면이 없다 — 그 결과를 전환 없이 즉시 적용해(`L.phaseStart`, 일시적 `is-skip`) 옛 장면이 비치지 않고, 새 장면은 첫 연출에서 나타난다.
- **페이즈 첫 칸을 만들 때 기준(2026-10-30 2장 P3에서 Em·G 비교가 남아 있던 사고)**: 첫 칸의 연출이 층을 갈아끼우는 것(`layer4`·`is-on` 토글)이면 앞 페이즈 장면은 첫 문구와 맞지 않는다 → 반드시 `enter`로 치운다. 앞 장면 위에서 이어 바꾸는 칸만 `enter`를 쓰지 않는다. 확인은 시뮬레이션 `allphases`처럼 "각 페이즈 시작 50ms 뒤 켜진 층"을 뽑아 본다.
- 빈 화면 동안은 진행 바가 잠긴다(`L.seeking`). 칸 터치·이전으로 페이즈를 오갈 때는 이미 `seek`가 무대를 새로 만들므로 이 규칙과 같다. 페이즈 안에서 칸을 넘길 때는 해당 없음.
- **페이즈 첫 문구는 앞 화면을 전제하지 않는다** — "그런데…", "…도 ~해요"처럼 바로 앞 장면에서 이어지는 연결어를 쓰지 않는다(빈 화면 뒤에 시작하므로 어색함). 2026-10-30 4장 P3·5장 P3·6장 P2·7장 P2·8장 P2 문구에서 연결어를 뺐다. "이번에도/이번엔/다음은"처럼 새 시작을 알리는 표현은 그대로 둔다.
- 새 강의의 페이즈 첫 칸은 앞 페이즈 끝 화면이 "새로 생성된" 상태에서 시작해도 말이 되게 설계한다.

- "다음"이 켜지는 조건: 칸이 끝나 멈춤(`L.ready`) 또는 수강 완료 유저(`L.rewatch`) 또는 이미 들은 칸(`L.step <= L.heard`). 처음 수강 중 안 들은 칸은 건너뛸 수 없다(칸 터치·다음 모두).
- 저장: `heard`는 localStorage `comboV2LecHeard`(`{챕터: 칸}`)에만 — 기기 한정, 지워져도 복구하지 않음. 수강 완료만 진행도 `_lec`(DB 동기화). 다시 열면 늘 처음부터 재생하고 `heard`는 이동 가능 범위에만 쓴다.
- 이탈은 기존 그대로(`close`·`abort`). 빨리 돌리던 중 닫히면 `L.seeking`을 `close`에서 풀어 둔다.

**게이지 움직임**
- 칸이 시작되면 칸 끝까지 `durs[i]` 동안 일정 속도로 찬다. 칸 끝 세로선에서 멈추고, 다음 칸은 지금 위치에서 이어서 찬다.
- 페이즈 마지막 칸이 끝나면 지금 위치에 고정(`pbarFreeze`)한 뒤 100%. 고정 없이 같은 100%를 다시 지정하면 브라우저가 진행 중인 느린 전환을 이어간다(화면은 끝났는데 게이지만 천천히 차던 버그).
- **transform만 쓴다**: 채움은 `scaleX`, 마커는 게이지 왼쪽 바깥에 둔 같은 폭의 레일(`#lec-pbar-rail`)을 `translateX(%)`로 옮김 → 레이아웃·페인트 없이 GPU 합성.

**`durs`(칸 길이) 측정**
- 칸 시작 → 칸이 끝나 멈춤(시뮬레이션 실측). 단계 연출·묶음·페이즈 구분·`CAPTION_GAP_MIN_MS`를 바꾸면 **모든 챕터를 다시 잰다**(2026-10-30 간격 3→4초 때 1~8장 전부 재측정).
- `.ms`(소리 꼬리까지 최소 시간)는 칸의 마지막 단계에 걸린다. 동요 단계는 14.5초.

**칸 만들기 도구**
- `chainSteps(list)`: 여러 단계를 한 칸으로 묶는다(지우지 않고 문구가 차례로 바뀜). 첫 단계의 `text`·`enter`가 칸의 것, 뒤 단계는 앞 문구가 최소 간격만큼 보인 뒤 `showCaption` + `enter` + 1초 + 연출. 낱개 배열(`STEPS_CHn_RAW`)을 두고 칸 기준으로 조립한다(7·8장). 뒤 단계의 `enter: clearScene`은 묶음 안에서도 동작한다.
- `clearScene()` = `layer4(null)`: 칸이 시작될 때(`enter`, 문구와 동시에) 직전 장면을 곧바로 치운다 — 새 장면은 1초 뒤 연출에서 나타난다. 장면이 이어지는 칸에는 쓰지 않는다(7장에서 확립, 8장도 같음).
- `hideNow`: 자기 단계 전에 보이면 안 되는 요소를 전환 없이 숨김.

**단계 설계 조건 — 빨리 돌리기가 화면을 정확히 재현하려면**
- 모든 지연·애니메이션은 엔진 함수로(`later`·`wait`·`anim`·`fx`·`swap` 등). `setTimeout`·`requestAnimationFrame` 직접 사용이나 CSS 애니메이션에만 의존하는 연출은 빨리 돌릴 때 빠지거나 늦게 나타난다.
- 소리는 `strum`·`note`·`piano`로(빨리 돌릴 땐 자동으로 안 남). 출력 trim 같은 오디오 상태 변경은 `endSkip`에서 되돌리는지 확인.
- 단계 하나에 핵심 하나. 레이아웃을 재는 연출(`fit7`·FLIP 등)은 빨리 돌리기에서 끝 화면이 맞는지 따로 검증.
- 요소를 다른 칸으로 옮기는 연출(8장 `reorderKey8`)은 DOM 순서가 바뀌므로 빨리 돌리기 결과와 순서까지 같은지 본다.

**전역 보호 (진행 바 연타에서 발견)**
- 이전/다음을 빠르게 누르면 더블탭 확대가 걸리는 사고가 있었다 → 앱 전체에 `html { touch-action: manipulation }`(style.css)과 확대된 상태에서 더블탭하면 원래 배율로 되돌리는 `_doubleTapZoomReset`(shared.js). iOS는 `user-scalable=no`로 이미 막힘. 더블탭 확대 기능 자체는 폐지가 아니라 보류.

**검증 방법 (가상 시계 시뮬레이션)**
- 모드: `dur`(칸 길이 실측) / `seek`(끝까지 재생하는 중 각 칸 시작 순간에 그 칸으로 이동 → 같은 화면인지) / `seekback`(수강 완료 유저, 거꾸로·점프 이동, 마지막 칸 동작) / `lock`(처음 수강 이동 제한, `<`·`>` 동작, 이전 페이즈 다 들은 상태) / `rules`(마커 멈춤, 버튼 글자, 자동 진행 없음). 화면 비교는 무대 DOM의 클래스·글자·인라인 스타일 스냅샷.

## 12. 8장 세부 (마이너 다이어토닉, 2026-10-30)
- 기준 key는 **Cm**(Eb·Ab·Bb). 도수는 7th 도수(`Im7 IIm7(b5) bIIIM7 IVm7 Vm7 bVIM7 bVII7`). 지정 운지는 `VOICINGS8`(`Cm7 x 3 5 3 4 3`, `Gm7 3 x 3 3 3 3`, `Fm7 x x 3 5 4 4`, `Dm7(b5) x 5 6 5 6 x`, `AbM7 4 x 5 5 4 x`, `G7 3 x 3 4 3 x`는 사용자 지정, `EbM7 x 6 5 3 3 3`·`Bb7 x 1 3 1 3 1`은 제안 후 승인).
- 칸(13): 페이즈 1 [①예고+마이너 스케일 ②4음 쌓기 ③이름·도수 비교+b 도수 ④시작음 C→A+구성이 같다 ⑤나란한 조 ⑥7코드 듣기] / 페이즈 2 [①Gm7 → Cm7(5도가 약함) ②하모닉 마이너 스케일 ③하모닉 7th 나열 ④G7만 차용+실전 7코드] / 페이즈 3 [①작은별 예고 ②마이너 작은별 ③소감+훈련 목표(둘로 나눔)+마무리]. 낱개 단계 21개를 `chainSteps`로 묶어 13칸.
- 층(`.lec3-l`): `lc8-a` 마이너 스케일 + 4줄 쌓기(1장 격자) / `lc8-t` 메이저 → 마이너 7코드 목록 / `lc8-k` 나란한 조(C 메이저 → A 마이너) / `lc8-sa`·`lc8-sb` 스케일 칸 두 벌 / `lc8-n`·`lc8-h` 7코드 목록(자연 / 하모닉) / `lc8-p` Gm7 → Cm7 / `lc8-song` 작은별 악보.
