# 코드 진행 보이싱 선택 알고리즘 ⛔🚨🚨

**절대 핵심 알고리즘 — 임의 변경 금지**

## 선택지 정의

각 코드는 두 가지 바레 보이싱 후보를 가진다:
- **5번줄 바레**: 근음 = 5번줄, 프렛 r (단, (9+r)%12 = 루트 피치클래스)
- **6번줄 바레**: 근음 = 6번줄, 프렛 r (단, (4+r)%12 = 루트 피치클래스)

## 알고리즘 3단계

### 규칙 1 — 첫 번째 코드: 최저 프렛
- prevCenterFret = null
- 두 후보 중 r이 작은 것(낮은 프렛) 선택

### 규칙 2 — 이후 코드: 루프 전체 이동 거리 최소화
- 단순 nearest-fret(greedy)이 아닌 **루프 전체 이동 합산 최소화**
- 마지막 코드 → 첫 번째 코드(다음 루프)로의 이동도 포함
- 모든 조합을 열거해 total cyclic distance 가장 작은 조합 선택

### 규칙 3 — 캐시 고정
- 최적 보이싱은 최초 1회 계산 후 `_stepCache`에 저장
- 재생 중 반복해도 동일 보이싱 유지 (재계산 없음)
- 키 변경 / 샵플랫 변경 시에만 재계산

## 예시: D# key I-V-vi-IV

| 코드 | 선택 | 근거 |
|------|------|------|
| D# (I) | 5번줄 6프렛 | 최저 프렛 |
| A# (V) | 6번줄 6프렛 | 이동 0 |
| Cm (vi) | 5번줄 3프렛 | 이동 3 |
| G# (IV) | 6번줄 4프렛 | 이동 1 (다음 루프 D#까지 고려) |
총 cyclic 이동 = 6

## 예시: F# key I-V-vi-IV

| 코드 | 선택 | 근거 |
|------|------|------|
| F# (I) | 6번줄 2프렛 | 최저 프렛 |
| C# (V) | 5번줄 4프렛 | 이동 2 |
| D#m (vi) | 5번줄 6프렛 | 이동 2 |
| B (IV) | 5번줄 2프렛 | 이동 4 (다음 루프 F#까지 고려) |
총 cyclic 이동 = 8
